Active Record

The activerecord plugin adds Active Record integration to the attachment interface. It is built on top of the model plugin.

Attachment​

Including a Shrine::Attachment module into an ActiveRecord::Base subclass will:

  • add model attachment methods
  • add validations and callbacks to tie attachment process to the record lifecycle

Callbacks​

After Save​

After a record is saved and the transaction is committed, Attacher#finalize is called, which promotes cached file to permanent storage and deletes previous file if any.

After Destroy​

After a record is destroyed and the transaction is committed, Attacher#destroy_attached method is called, which deletes stored attached file if any.

Caveats​

Active Record currently has a bug with transaction callbacks, so if you have any "after commit" callbacks, make sure to include Shrine's attachment module after they have all been defined.

Duplicating records​

Since a record being created can't yet have a confirmed attachment of its own to safely replace, Shrine never deletes the previous file when the attachment changes as part of creating a record, only when updating one. This matters most when duplicating a record: #dup performs a shallow copy, so a duplicated record initially points to the same underlying file as the original (they'll have the same attached file data), and replacing the attachment on the duplicate before it's ever saved won't affect the original:

Once photo2 has been saved, replacing its attachment again behaves normally (the previously attached file is deleted):

Keep in mind this only protects against replacing the attachment on create. As long as photo and photo2 continue to reference the same underlying file (i.e. photo2 is saved without ever changing its attachment), destroying either record will still delete the file the other one references, since Shrine has no way of knowing the file is shared:

Overriding callbacks​

You can override any of the following attacher methods to modify callback behaviour:

  • Attacher#activerecord_before_save
  • Attacher#activerecord_after_save
  • Attacher#activerecord_after_destroy

JSON columns​

When the data attribute is backed by a json or jsonb database column, Active Record already serializes hashes into JSON, so Shrine skips its own serialization to avoid double encoding.

By default this detection only looks at real database columns. If you declare the data attribute type via the Attributes API (e.g. on top of a text column), enable the :attribute_types option so it's recognized as well:

This option defaults to false for backwards compatibility.

Persistence​

The following persistence methods are added to Shrine::Attacher:

MethodDescription
Attacher#atomic_promotecalls Attacher#promote and persists if the attachment hasn't changed
Attacher#atomic_persistsaves changes if the attachment hasn't changed
Attacher#persistsaves any changes to the underlying record

See persistence docs for more details.
